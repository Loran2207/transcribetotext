Overlay motion

One curve and one pair of durations for everything that opens over the page. Opening is unhurried, closing is quick. Press Play on any card to replay it.

Tokens

/* opening is unhurried, closing is quick */
--motion-enter: cubic-bezier(0.22, 1, 0.36, 1);
--motion-exit:  cubic-bezier(0.4, 0, 1, 1);
--motion-dim:   200ms;   /* the dim behind    */
--motion-card:  260ms;   /* a centred card    */
--motion-sheet: 300ms;   /* a sheet on a phone */
--motion-out:   160ms;   /* every exit        */

Cardfrom 768px up

The sheet demo runs the phone keyframes at any window width so the movement can be seen here. In the product the sheet keyframes are inside @media (max-width: 767px), and the same element uses the card keyframes above that width.

Where each class goes

ClassPut it onWhy that one
ttt-dim DialogOverlay, AlertDialogOverlay, the scrim in ModalShell and in SearchModal Anything that dims the page behind an overlay.
ttt-modal-card DialogContent, AlertDialogContent A card centred with translate(-50%, -50%). The keyframe carries that translate, otherwise the card jumps to the corner while it animates.
ttt-modal-rise The card in ModalShell Same movement for a card centred by its flex parent, with no transform of its own.
ttt-modal-sheet MODAL_SURFACE in modal-surface.ts, and ModalShell Below 768 those surfaces dock to the bottom edge, so they travel their own height instead of zooming from the middle of the screen.
ttt-modal-sheet-sm AlertDialogContent The shadcn base still docks its confirmations at 640, not 768. Same keyframes, its own boundary.
ttt-search The panel in SearchModal Search is summoned from the top bar, so it arrives from above.

Three things this replaced

BeforeNow
The overlay ran 150ms and the dialog 200ms, so the dim finished first and the card arrived into an already dark screen. 200ms and 260ms on the same curve: the dim leads by a little and they settle together.
A dialog that is a sheet on a phone still animated zoom-in-95 from the centre of the screen. It travels its own height from the bottom edge.
No prefers-reduced-motion anywhere in the codebase. Every shape falls back to a 120ms fade with no movement.

If a surface is built with Framer Motion

The app already has motion/react. Same numbers, same curve.

const EASE_IN  = [0.22, 1, 0.36, 1];
const EASE_OUT = [0.4, 0, 1, 1];

// the dim
initial={{ opacity: 0 }}
animate={{ opacity: 1, transition: { duration: 0.2,  ease: EASE_IN  } }}
exit=   {{ opacity: 0, transition: { duration: 0.16, ease: EASE_OUT } }}

// a card
initial={{ opacity: 0, y: 14, scale: 0.965 }}
animate={{ opacity: 1, y: 0, scale: 1, transition: { duration: 0.26, ease: EASE_IN } }}
exit=   {{ opacity: 0, y: 8, scale: 0.985, transition: { duration: 0.16, ease: EASE_OUT } }}

// a sheet
initial={{ y: "100%" }}
animate={{ y: 0, transition: { duration: 0.3,  ease: EASE_IN  } }}
exit=   {{ y: "100%", transition: { duration: 0.16, ease: EASE_OUT } }}

// and honour the setting
const reduce = useReducedMotion();

Two rules

A stack of dialogs animates only the one that arrives. The layers underneath stay where they are; moving them turns a stack into a pile. The exit is never longer than the enter. A user who dismissed something is already looking somewhere else.
