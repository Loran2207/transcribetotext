How a dialog opens

The card arrives on a spring and its contents follow it in, a beat apart, in reading order. Press the button to open it, press it again to close it. Slow it down to see the parts.

The three parts

PartWhat it does
The dimFades and blurs the page behind it, 240ms. It never scales and never moves: it is the room going quiet, not an object arriving.
The cardRises 12px and scales 0.96 to 1 on a spring over 420ms, overshooting by 1.5%. Its opacity and a 3px blur clear in 220ms, so it is readable well before it has finished settling.
The contentsEach block rises 12px and fades over 320ms, starting 90ms after the card and 34ms apart in reading order. This is the part that makes it feel made.

Closing

140ms, no spring, no stagger, everything at once. Someone who dismissed a dialog is already looking somewhere else, and an exit that performs is an exit in the way.

The markup it runs on

<div class="ttt-dim"        data-state="open"></div>
<div class="ttt-modal-card" data-state="open">
  <div style="--i:0">title</div>
  <div style="--i:1">first field</div>
  <div style="--i:2">second field</div>
  <div style="--i:3">the buttons</div>
</div>

--i is the position in the queue. Without it every child animates
together, which still looks fine - the stagger is the polish, not
the mechanism. Radix writes data-state for you; a portal that mounts
only while open needs no attribute at all.

Where the numbers come from

ValueSource
The spring, bounce 0.2Apple's spring API takes a duration and a bounce; 0.1-0.3 is the band Emil Kowalski's animation standards call usable. Written as CSS linear(), which is how a spring is expressed without a JS library.
scale(0.96), 12px riseRadix Themes ships 0.97 and 5px. A spring travels further than an ease, so the distance goes up a little with it.
420ms in, 140ms outInside the 200-500ms band Emil's standards give for modals and drawers. Radix Themes is 200/100, shadcn's own Sheet 500/300.
The blur clearingEmil's tip: a 2-3px blur smooths a state change that would otherwise pop.
The staggerNot from a library. It is the difference between a dialog that appears and a dialog that arrives.

The same thing in Framer Motion

const spring = { type: "spring", duration: 0.42, bounce: 0.2 };

// the card
initial={{ opacity: 0, y: 12, scale: 0.96, filter: "blur(3px)" }}
animate={{ opacity: 1, y: 0, scale: 1, filter: "blur(0px)",
           transition: { ...spring, opacity: { duration: 0.22 }, filter: { duration: 0.22 } } }}
exit=   {{ opacity: 0, y: 4, scale: 0.99, transition: { duration: 0.14 } }}

// each block inside it
variants={{ show: (i) => ({ opacity: 1, y: 0,
  transition: { duration: 0.32, delay: 0.09 + i * 0.034, ease: [0.16, 1, 0.3, 1] } }) }}

const reduce = useReducedMotion();  // and honour it
